# مستند کامل توکن‌سازی در شبکه ملی سلامت
## مبتنی بر Hyperledger Fabric
### نسخه کامل – همه بخش‌ها

**نسخه:** 1.0  
**تاریخ:** اوت ۲۰۲۶  
**مرتبط با:** پروژه تبدیل 6G-Network به شبکه ملی سلامت

این مستند چارچوب کامل **توکن‌سازی** را برای تمام بخش‌های سامانه (منابع فیزیکی، دارو، خون، نیروی انسانی، بیمه، رضایت بیمار، بحران و بازار) تعریف می‌کند.

---

# ۱. اهداف توکن‌سازی

- تبدیل منابع، حقوق و ارزش‌ها به دارایی‌های دیجیتال قابل ردیابی و قابل معامله
- ایجاد بازار شفاف و خودکار برای تخصیص بهینه منابع در سطح محلی، منطقه‌ای و ملی
- حفظ قابلیت ممیزی کامل و انطباق با قوانین سلامت و حریم خصوصی
- گسترش ایده «بازار منابع» پروژه اصلی 6G به حوزه سلامت

# ۳. کانال‌های جدید مرتبط با توکن (۸ کانال)

### TokenChannel
کانال اصلی مدیریت چرخه عمر تمام توکن‌ها. عملیات mint، burn، transfer و query در سطح پایه اینجا انجام می‌شود. سیاست تأیید متوسط برای جلوگیری از ایجاد توکن غیرمجاز اعمال می‌گردد.

### ResourceTokenChannel
مخصوص توکن‌های منابع فیزیکی (Bed، OR، Equipment، Lab). متادیتای مکانی و زمانی توکن‌ها در این کانال نگهداری می‌شود. بازار محلی و منطقه‌ای منابع از این کانال تغذیه می‌کند.

### DrugTokenChannel
مدیریت توکن‌های دارو و مواد تحت کنترل. ردیابی بچ، تاریخ انقضا و شرایط نگهداری در این کانال متمرکز است. ارتباط مستقیم با کانال‌های Inventory و NationalDrugTraceability دارد.

### StaffTokenChannel
توکن‌های نیروی انسانی و ساعات کار متخصصان. صلاحیت، تخصص و محدودیت‌های زمانی در متادیتای توکن ذخیره می‌شود. برای بازار اشتراک نیروی انسانی استفاده می‌گردد.

### ClaimTokenChannel
مدیریت توکن‌های مطالبات بیمه‌ای و تبدیل آن‌ها به PaymentToken. وضعیت تأیید، رد یا در حال بررسی مطالبه در این کانال ثبت می‌شود.

### ConsentTokenChannel
صدور، استفاده و ابطال توکن‌های رضایت بیمار. محدوده دسترسی، مدت اعتبار و گیرندگان مجاز در خود توکن کد می‌شود. حساس‌ترین کانال از نظر حریم خصوصی است.

### CrisisTokenChannel
صدور و توزیع توکن‌های اولویت بحران توسط سازمان‌های ملی. این توکن‌ها در تخصیص منابع اضطراری وزن بیشتری دارند و پس از پایان بحران منقضی می‌شوند.

### TokenMarketChannel
بازار معامله تمام انواع توکن‌های قابل معامله. لیست پیشنهادها، قیمت‌ها، قفل‌ها و تسویه‌ها در این کانال ثبت می‌گردد. موتور اصلی اقتصاد منابع شبکه است.

# ۴. ساختار داده پیشنهادی توکن (Go)

```go
type Token struct {
    TokenID        string            `json:"tokenId"`
    TokenType      string            `json:"tokenType"`      // BED, OR, DRUG, ...
    OwnerMSP       string            `json:"ownerMsp"`
    IssuerMSP      string            `json:"issuerMsp"`
    Amount         int64             `json:"amount"`         // برای توکن‌های قابل تقسیم
    Metadata       map[string]string `json:"metadata"`       // نوع تخت، بچ دارو، تخصص و ...
    Status         string            `json:"status"`         // ACTIVE, LOCKED, BURNED, EXPIRED
    IssuedAt       string            `json:"issuedAt"`
    ExpiresAt      string            `json:"expiresAt"`
    ParentTokenID  string            `json:"parentTokenId"`  // برای توکن‌های مشتق‌شده
    TransferHistory []TransferRecord `json:"transferHistory"`
}

type TransferRecord struct {
    FromMSP   string `json:"fromMsp"`
    ToMSP     string `json:"toMsp"`
    Timestamp string `json:"timestamp"`
    TxID      string `json:"txId"`
}
```

# ۵. قراردادهای هوشمند توکن‌سازی (کامل – بیش از ۶۰ قرارداد)

هر قرارداد حداقل ۳ خط توضیح دارد.

## ۵.۱ قراردادهای پایه مدیریت توکن

**MintToken**  
ایجاد توکن جدید از نوع مشخص توسط سازمان مجاز. متادیتا، مقدار و تاریخ انقضا تنظیم می‌شود. فقط سازمان‌های دارای نقش Issuer می‌توانند این عمل را انجام دهند.

**BurnToken**  
سوزاندن دائمی توکن پس از مصرف یا ابطال. وضعیت به BURNED تغییر و تاریخچه حفظ می‌شود. این عمل غیرقابل بازگشت است و موجودی را کاهش می‌دهد.

**TransferToken**  
انتقال مالکیت توکن از یک سازمان به سازمان دیگر. تاریخچه انتقال ثبت و وضعیت به‌روزرسانی می‌شود. بررسی‌های امنیتی و رضایت (در صورت نیاز) انجام می‌گردد.

**LockToken**  
قفل موقت توکن برای جلوگیری از انتقال یا استفاده همزمان. معمولاً در حین مذاکره معامله استفاده می‌شود. قفل دارای زمان انقضا است.

**UnlockToken**  
باز کردن قفل توکن پس از تکمیل یا لغو معامله. توکن دوباره قابل انتقال یا استفاده می‌شود. فقط صاحب فعلی یا قرارداد بازار می‌تواند قفل را باز کند.

**ExpireToken**  
ابطال خودکار یا دستی توکن‌های منقضی‌شده. وضعیت به EXPIRED تغییر می‌کند. برای توکن‌های دارو، خون و رضایت بسیار حیاتی است.

**QueryToken**  
بازیابی اطلاعات کامل یک توکن بر اساس TokenID. شامل متادیتا، وضعیت و تاریخچه انتقال است. دسترسی بر اساس نقش کنترل می‌شود.

**QueryTokenBalance**  
محاسبه موجودی توکن‌های یک سازمان بر اساس نوع توکن. برای گزارش‌گیری و تصمیم‌گیری بازار استفاده می‌شود. نتیجه به صورت تجمیعی بازگردانده می‌شود.

**QueryTokenHistory**  
بازیابی تاریخچه کامل ایجاد، انتقال و تغییرات یک توکن. برای ممیزی و ردیابی ضروری است. تمام تراکنش‌های مرتبط لیست می‌شوند.

**UpdateTokenMetadata**  
به‌روزرسانی متادیتای توکن (مثلاً تغییر وضعیت نگهداری دارو). تغییرات ثبت و تاریخچه حفظ می‌شود. فقط صادرکننده یا صاحب فعلی مجاز است.

## ۵.۲ قراردادهای توکن منابع فیزیکی (Bed / OR / Equipment / Lab)

**MintBedToken**  
ایجاد توکن از ظرفیت تخت آزاد. متادیتا شامل نوع تخت، بخش، ویژگی‌های خاص (ایزوله و غیره) است. پس از mint، تخت از موجودی آزاد کسر می‌شود.

**BurnBedToken**  
سوزاندن توکن تخت پس از تخصیص واقعی به بیمار. پیوند بین توکن و پذیرش بیمار ایجاد می‌شود. ظرفیت واقعی و توکنی همگام می‌ماند.

**MintORToken**  
ایجاد توکن اسلات اتاق عمل برای بازه زمانی مشخص. تداخل زمانی بررسی و از دوباره‌کاری جلوگیری می‌شود. متادیتا شامل نوع عمل و تجهیزات مورد نیاز است.

**BurnORToken**  
سوزاندن توکن اتاق عمل پس از اتمام یا لغو جراحی. زمان واقعی استفاده ثبت می‌شود. بهره‌وری اتاق عمل قابل محاسبه می‌گردد.

**MintEquipmentToken**  
ایجاد توکن زمان استفاده از تجهیزات گران‌قیمت. مدت و نوع تجهیز در متادیتا ذخیره می‌شود. امکان معامله زمان تجهیزات بین مراکز فراهم است.

**BurnEquipmentToken**  
سوزاندن توکن تجهیزات پس از استفاده واقعی. ساعات کارکرد ثبت و برای نگهداری پیشگیرانه استفاده می‌شود. ردیابی دقیق استفاده تضمین می‌گردد.

**MintLabToken**  
ایجاد توکن ظرفیت آزمایشگاهی برای نوع آزمایش مشخص. زمان‌بندی و محدودیت‌ها در متادیتا قرار می‌گیرد. اشتراک ظرفیت آزمایشگاهی تسهیل می‌شود.

**BurnLabToken**  
سوزاندن توکن آزمایشگاه پس از انجام آزمایش. نتیجه آزمایش می‌تواند به توکن پیوند داده شود. چرخه کامل از ظرفیت تا نتیجه ثبت می‌گردد.

## ۵.۳ قراردادهای توکن دارو و خون

**MintDrugToken**  
ایجاد توکن برای واحد یا بچ دارو. شماره بچ، تاریخ انقضا، شرایط نگهداری و تولیدکننده در متادیتا ذخیره می‌شود. ردیابی از لحظه ورود به سیستم آغاز می‌گردد.

**BurnDrugToken**  
سوزاندن توکن دارو پس از تحویل به بیمار یا مصرف. پیوند به نسخه و بیمار ایجاد می‌شود. چرخه ردیابی دارو کامل می‌گردد.

**MintBloodToken**  
ایجاد توکن برای واحد خون یا فرآورده. گروه خونی، تاریخ اهدا و انقضا در متادیتا ثبت می‌شود. مدیریت موجودی خون دقیق‌تر می‌شود.

**BurnBloodToken**  
سوزاندن توکن خون پس از تزریق به بیمار. واکنش احتمالی و زمان تزریق ثبت می‌شود. ایمنی و ردیابی کامل تضمین می‌گردد.

**ExpireDrugOrBloodToken**  
ابطال خودکار توکن‌های دارو یا خون منقضی‌شده. هشدار به صاحب توکن ارسال و موجودی اصلاح می‌شود. جلوگیری از استفاده از محصولات منقضی هدف است.

**QuarantineToken**  
قرنطینه توکن دارو یا خون مشکوک. وضعیت به QUARANTINED تغییر و استفاده مسدود می‌شود. تحقیقات بعدی ثبت می‌گردد.

## ۵.۴ قراردادهای توکن نیروی انسانی

**MintStaffToken**  
ایجاد توکن ساعت کار یا شیفت متخصص. تخصص، صلاحیت و محدودیت‌های زمانی در متادیتا ذخیره می‌شود. بازار اشتراک نیروی انسانی فعال می‌گردد.

**BurnStaffToken**  
سوزاندن توکن پس از انجام خدمت واقعی. ساعات واقعی کار ثبت و با توکن مطابقت داده می‌شود. تسویه عادلانه تضمین می‌گردد.

**TransferStaffToken**  
انتقال توکن نیروی انسانی بین مراکز. صلاحیت مقصد بررسی می‌شود. پشتیبانی متقابل نیروی انسانی تسهیل می‌گردد.

## ۵.۵ قراردادهای توکن رضایت (ConsentToken)

**MintConsentToken**  
ایجاد توکن رضایت بیمار با محدوده داده، مدت اعتبار و گیرندگان مجاز. توکن فقط توسط دارنده معتبر قابل استفاده است. کنترل دقیق حریم خصوصی فراهم می‌شود.

**UseConsentToken**  
استفاده از توکن رضایت برای دسترسی به داده. بررسی اعتبار، محدوده و انقضا انجام می‌شود. هر استفاده ثبت و قابل ممیزی است.

**RevokeConsentToken**  
ابطال توکن رضایت توسط بیمار یا نماینده قانونی. از لحظه ابطال، دسترسی‌های مبتنی بر آن قطع می‌شود. حق بیمار برای لغو رضایت محترم شمرده می‌شود.

**QueryConsentTokenStatus**  
بررسی وضعیت فعلی یک توکن رضایت. اعتبار، استفاده‌های قبلی و انقضا نمایش داده می‌شود. شفافیت برای بیمار و ارائه‌دهنده فراهم است.

## ۵.۶ قراردادهای توکن بیمه و مالی

**MintClaimToken**  
تبدیل مطالبه بیمه‌ای به توکن. مبلغ، خدمات و وضعیت اولیه در متادیتا ذخیره می‌شود. مطالبات به دارایی دیجیتال تبدیل می‌گردند.

**UpdateClaimTokenStatus**  
به‌روزرسانی وضعیت توکن مطالبه (در حال بررسی، تأیید شده، رد شده). دلیل تغییر ثبت می‌شود. شفافیت فرآیند بیمه افزایش می‌یابد.

**ConvertClaimToPayment**  
تبدیل ClaimToken تأییدشده به PaymentToken. مبلغ نهایی و گیرنده مشخص می‌شود. تسویه خودکار مطالبات ممکن می‌گردد.

**MintPaymentToken**  
ایجاد توکن پرداخت برای تسویه بین طرفین. قابل انتقال و قابل استفاده برای پرداخت‌های بعدی است. جریان مالی شفاف و قابل ردیابی می‌شود.

**TransferPaymentToken**  
انتقال توکن پرداخت بین سازمان‌ها. برای تسویه بین‌مرکزی و پرداخت به تأمین‌کنندگان استفاده می‌شود. سرعت و شفافیت مالی افزایش می‌یابد.

**BurnPaymentToken**  
سوزاندن توکن پرداخت پس از تسویه نهایی. چرخه مالی کامل و بسته می‌شود. جلوگیری از استفاده مضاعف تضمین می‌گردد.

## ۵.۷ قراردادهای توکن بحران

**MintCrisisToken**  
صدور توکن اولویت بحران توسط سازمان‌های ملی مجاز. سطح اولویت و مدت اعتبار تعیین می‌شود. در تخصیص منابع وزن بیشتری ایجاد می‌کند.

**UseCrisisToken**  
استفاده از توکن بحران برای افزایش اولویت درخواست منبع. توکن پس از استفاده سوزانده یا کاهش می‌یابد. تخصیص عادلانه در شرایط اضطراری تسهیل می‌گردد.

**ExpireCrisisToken**  
ابطال توکن‌های بحران پس از پایان وضعیت اضطراری. تمام توکن‌های فعال منقضی می‌شوند. بازگشت به حالت عادی تضمین می‌گردد.

## ۵.۸ قراردادهای بازار توکن

**ListTokenForSale**  
عرضه توکن در بازار با تعیین قیمت و شرایط. توکن قفل و در لیست پیشنهادها قرار می‌گیرد. شروع فرآیند معامله است.

**CancelTokenListing**  
لغو عرضه توکن قبل از پذیرش. قفل باز و توکن به صاحب برمی‌گردد. انعطاف‌پذیری عرضه‌کننده حفظ می‌شود.

**BuyToken**  
خرید توکن از بازار. پرداخت انجام، مالکیت منتقل و قفل باز می‌شود. معامله اتمیک و ایمن است.

**SettleTokenTrade**  
تسویه نهایی معامله توکن شامل انتقال مالکیت و پرداخت. وضعیت معامله به تکمیل‌شده تغییر می‌کند. اعتماد به بازار تقویت می‌گردد.

**QueryMarketListings**  
جستجوی پیشنهادات فعال توکن بر اساس نوع، قیمت و موقعیت. فیلترهای پیشرفته پشتیبانی می‌شود. یافتن منابع مورد نیاز تسهیل می‌گردد.

**LockTokenForTrade**  
قفل توکن در حین مذاکره یا معامله. از فروش همزمان جلوگیری می‌کند. اطمینان طرفین افزایش می‌یابد.

**ReleaseTokenLock**  
باز کردن قفل پس از تکمیل یا لغو معامله. توکن دوباره در دسترس قرار می‌گیرد. گردش بازار حفظ می‌شود.

**UpdateTokenPrice**  
به‌روزرسانی قیمت پیشنهاد توکن. تغییرات ثبت و به متقاضیان منعکس می‌شود. انعطاف‌پذیری قیمت‌گذاری فراهم است.

**RateTokenProvider**  
ثبت امتیاز و بازخورد در مورد ارائه‌دهنده توکن. اعتبار عرضه‌کنندگان ساخته می‌شود. کیفیت بازار از طریق بازخورد بهبود می‌یابد.

**GenerateTokenMarketReport**  
تولید گزارش فعالیت بازار توکن شامل حجم، قیمت میانگین و انواع توکن. برای تحلیل و سیاست‌گذاری استفاده می‌شود. شفافیت اقتصاد منابع افزایش می‌یابد.

## ۵.۹ قراردادهای کمکی و پیشرفته

**SplitToken**  
تقسیم یک توکن به چند توکن کوچکتر (مثلاً تقسیم ساعت کار). مجموع مقدار حفظ می‌شود. انعطاف‌پذیری معامله افزایش می‌یابد.

**MergeTokens**  
ادغام چند توکن هم‌نوع به یک توکن بزرگتر. مالکیت و متادیتا یکسان‌سازی می‌شود. مدیریت موجودی ساده‌تر می‌گردد.

**FreezeToken**  
مسدود کردن موقت توکن به دستور مرجع نظارتی. استفاده و انتقال متوقف می‌شود. ابزار حاکمیتی برای موارد خاص فراهم است.

**UnfreezeToken**  
رفع مسدودی توکن پس از رفع مشکل. وضعیت به ACTIVE برمی‌گردد. بازگشت کنترل‌شده به چرخه عادی ممکن می‌شود.

**AuditToken**  
ممیزی کامل یک توکن یا مجموعه توکن‌های یک سازمان. تمام رویدادها استخراج و گزارش می‌شود. شفافیت و پاسخگویی تضمین می‌گردد.

**BatchMintTokens**  
ایجاد دسته‌ای چندین توکن هم‌نوع در یک تراکنش. برای کارایی در مقیاس بالا استفاده می‌شود. کاهش سربار شبکه هدف است.

**BatchTransferTokens**  
انتقال دسته‌ای چندین توکن. برای تسویه‌های بزرگ یا توزیع بحران مناسب است. کارایی عملیات گروهی افزایش می‌یابد.

**QueryExpiringTokens**  
یافتن توکن‌هایی که در آستانه انقضا هستند. هشدار به صاحبان ارسال می‌شود. مدیریت پیشگیرانه انقضا تسهیل می‌گردد.

**ValidateTokenRules**  
اعتبارسنجی قوانین کسب‌وکار مرتبط با یک توکن (مثلاً آیا می‌توان دارو را معامله کرد). قبل از هر عمل مهم فراخوانی می‌شود. انطباق خودکار تضمین می‌گردد.

**LinkTokenToRealAsset**  
پیوند توکن به دارایی فیزیکی واقعی (تخت، دستگاه، واحد دارو). همگام‌سازی وضعیت فیزیکی و دیجیتال حفظ می‌شود. جلوگیری از ایجاد توکن بدون پشتوانه هدف است.

# ۶. سیاست‌های تأیید پیشنهادی برای توکن‌ها

- **Mint** توکن‌های منابع محلی: تأیید سازمان صادرکننده + یک سازمان ناظر محلی
- **Mint** توکن‌های ملی (Crisis، CapacityCredit): تأیید حداقل دو سازمان ملی (Org1 + Org2 یا Org35)
- **Transfer** توکن‌های حساس (Consent، Drug): تأیید صاحب فعلی + بررسی رضایت یا قوانین
- **Burn** توکن‌های مصرفی: تأیید سازمان مصرف‌کننده
- **بازار**: تأیید دو طرف معامله + قرارداد بازار

---

# ۷. یکپارچه‌سازی با بخش‌های قبلی سامانه

- کانال‌های BedChannel، MedicationChannel و غیره همچنان وضعیت فیزیکی را نگه می‌دارند.
- توکن‌ها به عنوان لایه ارزش و معامله روی آن‌ها قرار می‌گیرند.
- هر تغییر فیزیکی مهم (تخصیص تخت، تحویل دارو) باید با burn یا mint متناظر توکن همراه باشد.
- بازار قبلی منابع اکنون از طریق TokenMarketChannel و توکن‌ها اجرا می‌شود.

# ۸. نقشه راه پیاده‌سازی توکن‌سازی

**فاز ۱ (۴–۶ هفته)**  
- پیاده‌سازی Token پایه + BedToken + ORToken  
- کانال‌های TokenChannel و ResourceTokenChannel  
- بازار محلی ساده

**فاز ۲ (۶–۸ هفته)**  
- DrugToken + BloodToken + ردیابی انقضا  
- StaffToken  
- ConsentToken

**فاز ۳ (۸–۱۰ هفته)**  
- ClaimToken + PaymentToken  
- CrisisToken  
- بازار منطقه‌ای و ملی کامل

**فاز ۴**  
- بهینه‌سازی عملکرد، Batch operations و گزارش‌های پیشرفته  
- اتصال به سیستم‌های پرداخت واقعی (در صورت نیاز)

---

# ۹. مزایای نهایی توکن‌سازی

- ایجاد اقتصاد واقعی منابع در نظام سلامت
- تخصیص بهینه‌تر ظرفیت در شرایط عادی و بحران
- ردیابی کامل و غیرقابل‌انکار از تولید تا مصرف
- انگیزه اقتصادی برای مراکز جهت بهینه‌سازی و اشتراک منابع
- پایه مناسب برای مدل‌های پیشرفته‌تر (بیمه پارامتریک، تأمین مالی مبتنی بر توکن و غیره)

**پایان مستند کامل توکن‌سازی**

این مستند همراه با مستندات قبلی (سازمان‌ها، کانال‌ها و ۳۵۰+ قرارداد) مجموعه کاملی برای پیاده‌سازی شبکه ملی سلامت مبتنی بر Hyperledger Fabric با قابلیت توکن‌سازی فراهم می‌کند.
